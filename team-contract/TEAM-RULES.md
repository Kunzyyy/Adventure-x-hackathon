# 团队协作边界：哪些事不能各自决定

## 1. 前端不能自行改变

- 不能自行改五个 API 的路径。
- 不能自行改请求或响应字段名。
- 不能自行改变字段层级，例如把 `data.resume` 改成其他位置。
- 不能跳过求职者事实确认步骤。
- 不能把未确认或已删除的事实发送给简历生成接口。
- 不能丢弃 `sourceQuote`、`evidenceIds`、`missingInformation` 或 `interviewRisks`。
- 不能把 `mock`、`live`、`fallback` 三种状态当成同一种结果。
- 不能假设后端会生成 PDF；后端只返回结构化简历内容。
- 不能自行增加登录、数据库、投递、收件箱、候选人评分或排名流程。

## 2. AI 与后端不能自行改变

- 不能静默修改 API 路径、字段名、必填规则或响应层级。
- 不能把求职者问题数量改出 5—8 道范围。
- 不能把企业问题数量改出 3—5 道范围。
- 不能让未确认事实进入最终简历。
- 不能生成没有有效 `evidenceIds` 的核心简历内容。
- 不能把“参与”擅自改成“负责”，把“了解”改成“熟练”或“精通”。
- 不能虚构公司、项目、技能、数字、奖项或工作结果。
- 不能给企业生成性别、年龄、婚育、籍贯、外貌等歧视性条件。
- 不能把筛选维度描述成 AI 自动录用或淘汰决定。
- 不能在日志中打印用户完整简历、完整回答或个人敏感信息。

## 3. 当前 MVP 明确不做

- 企业上传多份简历。
- AI 对候选人评分、排名或淘汰。
- 求职者投递和企业收件箱。
- 企业账号、登录和权限。
- 数据库和云端个人简历存储。
- 双方聊天、面试安排和招聘状态管理。
- 真实岗位发布平台。
- 后端 PDF 生成和页面视觉样式。

如果某个页面依赖上述功能，应先停下来讨论是否超出三天 MVP，而不是直接添加。

## 4. 哪些内容可以各自处理

前端可以独立处理：

- 页面颜色、排版、组件和动画。
- 表单输入体验。
- 加载和错误提示的视觉表现。
- 结构化内容的编辑和复制交互。

AI 与后端可以独立处理：

- Prompt 的具体写法。
- 模型调用的内部实现。
- 超时时间、重试和错误处理。
- JSON 解析和 Zod 校验。
- MOCK、live 和 fallback 的内部切换。
- 后端测试和反编造测试。

前提是这些内部调整不能改变 [API-CONTRACT.md](./API-CONTRACT.md) 中前端能看到的契约。

## 5. 确实需要修改契约时

必须按下面顺序处理：

1. 在群里说明为什么要改、影响哪个页面。
2. 更新 `API-CONTRACT.md` 和对应示例。
3. 求职者端、企业端或后端中受影响的成员明确确认。
4. 确认后再修改代码和联调。

不能先改代码，再要求其他成员被动适配。
